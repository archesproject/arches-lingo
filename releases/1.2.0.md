## Arches Lingo 1.2.0 Release Notes

This release is in development. Summarize the theme of the release here before publishing.

### Dependencies

```
Python:
    No changes

JavaScript:
    No changes
```

### Added

-   `add_missing_languages` management command, which adds a `languages` row for
    every language code found in resource data that does not have one, deriving
    the name and text direction from Django's language list and the IANA
    Language Subtag Registry.
-   Thesaurus export now supports exporting to N-Triples or Turtle formats
-   Thesaurus import now accepts Turtle (`.ttl`) and N-Triples (`.nt`) files
    alongside RDF/XML (`.xml`, `.rdf`). The serialization is selected from the
    file extension. Note that `.rdf` on import means RDF/XML SKOS, which is a
    different serialization than the Arches-ontology RDF written by the `rdf`
    export format, so a `.rdf` file produced by Lingo's own export is not
    itself a valid import input.
-   Concept merge workflow. From a concept's header, an editor can pick
    another concept to merge into the one they are viewing, choose which of
    its labels, notes, relationships, matches, and images to carry across,
    and resolve preferred label conflicts by demoting labels to alternate
    labels. Duplicate values are skipped, and a reciprocal `exactMatch` is
    recorded between the two concepts so the absorbed concept's URI still
    leads to the survivor. Within a scheme, the absorbed concept (which must
    be in the Editing or Draft state) can be retired as part of the same
    merge -- or deleted, if it is a draft, since a draft has no URI to keep
    resolvable -- with its narrower concepts moved to the surviving concept or
    to its own broader concepts, orphaned, or removed along with it. Concepts can also be
    merged across schemes, in which case scheme-specific values (hierarchy, top
    concept, and related concepts) are not copied and the absorbed concept is
    left in place. Each merge is recorded, and the concept header shows the
    merge history for both concepts; a merge across schemes appears only on
    the surviving concept, as values copied from the other. Merging requires
    the surviving concept's scheme to be unlocked unless the user is a Lingo
    administrator.
-   Concept match detection, for finding concepts that probably mean the same
    thing. From the new Find Matches page (in the side navigation, or from a
    concept's header to search for that concept's matches), an editor starts a
    run over every scheme or chosen schemes, optionally narrowed to a concept
    set, particular concepts, or only pairs that span two schemes. A run
    compares concepts by shared URI, exact label, or similar label (with an
    adjustable similarity threshold), and by default compares labels only
    within the same language; retired concepts are left out. The page shows a
    run's progress while it works, and its pairs can be filtered by label.
    Each candidate pair can then be linked with a reciprocal `exactMatch`,
    `closeMatch` or `relatedMatch`, merged using the concept merge workflow,
    or dismissed, singly or in bulk, and dismissed pairs can be restored. A
    decision about a pair applies in every run, including later ones, and is
    kept when a run is deleted. Pairs already linked by any match relation or
    merged are not suggested again, and merging two concepts anywhere in Lingo
    settles the pair; when the merge retires or deletes the absorbed concept,
    its other open pairs pass to the surviving concept. Runs are kept so they
    can be reviewed later, and can be cancelled or deleted by the editor who
    started them or by a Lingo administrator. Runs execute on a Celery worker; the new
    `detect_concept_matches` management command runs one from the command
    line when no worker is available, and its results can be reviewed in the
    browser in the same way.

### Changed

-   `dump_lingo_fixtures` now includes the language records the archived data's
    language codes refer to, and `load_lingo_fixtures` merges them into the
    target install's existing languages rather than replacing them. Archives
    written before this change still load.
-   Retiring or deleting a concept now indexes every affected concept in a
    single pass once the change is committed, instead of reindexing once per
    narrower concept that is moved, which makes these operations noticeably
    faster on concepts with many children.

### Fixed

-   Labels, notes, and other language-tagged values imported with a language
    code that has no `languages` row no longer display blank in the Language
    widget.

### Upgrading

1. Upgrade the Python package:

    ```
    pip install --upgrade arches-lingo
    ```

2. Run migrations:

    ```
    python manage.py migrate
    ```

3. Rebuild the frontend:

    ```
    npm install
    npm run build_development
    python manage.py collectstatic
    ```

4. Concept match detection runs on a Celery worker, so make sure one is
   running. Searching a whole vocabulary can occupy a worker for tens of
   minutes, so on a production server consider giving match detection its own
   queue by adding the following to your project's `settings.py` or
   `settings_local.py`:

    ```
    LINGO_MATCH_TASK_QUEUE = "lingo_matching"
    ```

    and starting a worker for that queue alongside your usual one:

    ```
    celery -A <project> worker -Q lingo_matching
    ```

    If the setting is left unset, match detection uses the default queue.

5. If you are running Arches on Apache, restart your server:
    ```
    sudo service apache2 reload
    ```
